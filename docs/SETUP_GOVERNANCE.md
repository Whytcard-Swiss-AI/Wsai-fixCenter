# Setup governance

Agent tools create overlapping project and user configuration: `.codex`, `.cursor`, `.agents`, `.claude`, `.gemini`, `.copilot`, MCP files, instruction files and account-specific environment. wsai_fckdot does not pretend these formats share one native precedence system. It provides one canonical project manifest and generates narrow adapters for the tools that need them.

## The simple mental model

```text
.wsai_fckdot/setup.json                  one source of truth
├── instructions                      rules written once
├── profiles                          account labels + env references
└── tools                             adapters to generate
    ├── AGENTS.md
    ├── .cursor/rules/wsai_fckdot.mdc
    ├── CLAUDE.md
    ├── GEMINI.md
    └── .github/copilot-instructions.md
```

wsai_fckdot also generates `.wsai_fckdot/profiles/<name>.ps1` and `.sh`. These profile activators contain variable names only. They validate every source, clear the target variables, then map values in memory from the selected source variables. Profile bindings never accept credential values. Free-form instructions reject common credential patterns, but users must still avoid placing secrets there.

## Safe four-step workflow

1. `get_setup_catalog`: understand supported adapters; no machine access.
2. `inspect_setup`: list known tool folders, instruction layers, configuration-file metadata and relevant environment-variable names. It returns no variable values or instruction/configuration contents.
3. `plan_setup`: compare a secret-free manifest to the exact workspace. It returns only `create`, `update`, `unchanged`, `retire` or `blocked` actions. The plan ID is bound to that workspace.
4. `apply_setup`: submit the same manifest, exact `plan_id` and `consent=true`.

If a selected adapter path contains a file not marked as generated by wsai_fckdot, the plan is blocked. An unselected user-owned adapter is left alone. wsai_fckdot will not guess which instructions should win and will not overwrite that file. Existing generated files are backed up under `.wsai_fckdot/backups/<plan_id>/` before updates. Generated adapters and profile activators removed from the manifest are moved—not deleted—to `.wsai_fckdot/retired/<plan_id>/`, preventing orphan instructions from remaining active. Application takes an exclusive wsai_fckdot workspace lock and rechecks every target against the approved state immediately before mutation.

## Account profiles

A profile is deliberately not an account database. It contains:

- a safe local label such as `personal`, `work` or `client-a`;
- target variable names expected by tools;
- references such as `env:OPENAI_WORK_API_KEY`.

It must never contain a credential value. For example:

```json
{
  "personal": {
    "account_label": "personal",
    "variables": {
      "OPENAI_API_KEY": "env:OPENAI_PERSONAL_API_KEY"
    }
  }
}
```

Activate a generated profile before starting an agent tool:

```powershell
. .\.wsai_fckdot\profiles\personal.ps1
```

```bash
source .wsai_fckdot/profiles/personal.sh
```

The activator fails clearly if a referenced source variable is missing. Switching profiles clears all target variables declared by the manifest first, preventing values from two accounts from remaining mixed in the same shell.

## Instruction conflicts and precedence

Different clients merge instructions differently. wsai_fckdot therefore distinguishes declared project policy from client behavior:

1. one-off invocation overrides;
2. the active wsai_fckdot profile's environment references;
3. canonical project instructions generated by wsai_fckdot;
4. unmanaged tool-specific project instructions;
5. user/global tool configuration.

This list is a governance model, not a claim that every client implements the same precedence. The inventory flags multiple instruction layers, and unmanaged layers must be reconciled by a person before wsai_fckdot can own their target paths.

Current adapters follow documented locations: Cursor project rules use `.cursor/rules`, while GitHub Copilot repository instructions use `.github/copilot-instructions.md`. `AGENTS.md` is generated as the shared agent-facing layer. See the [Cursor rules documentation](https://docs.cursor.com/context/rules) and [GitHub Copilot custom-instruction support](https://docs.github.com/en/copilot/reference/custom-instructions-support).

## What happens to the hundreds of other `.xxx` folders?

wsai_fckdot inventories every top-level dot-directory within a strict entry limit. Known agent-tool surfaces are classified. Unknown names are counted but hidden by default; returning their names requires `include_unknown_names=true`. wsai_fckdot does not delete, move or merge unknown folders. New tool adapters can be added to the public registry without changing the canonical manifest format.

Home-directory inspection is optional and read-only. Setup application is workspace-only: wsai_fckdot refuses to apply a setup directly at the filesystem root or user home.

## Example MCP calls

Inventory one workspace:

```json
{
  "root": "/absolute/path/to/project",
  "consent": true,
  "include_home": false,
  "include_unknown_names": false
}
```

Plan with [`setup.example.json`](../setup.example.json) as the `manifest`, review every action and retain the returned `plan_id`. Apply only after that review:

```json
{
  "root": "/absolute/path/to/project",
  "manifest": {
    "version": 1,
    "active_profile": "personal",
    "profiles": {
      "personal": {
        "account_label": "personal",
        "variables": {
          "OPENAI_API_KEY": "env:OPENAI_PERSONAL_API_KEY"
        }
      }
    },
    "instructions": ["Run the smallest relevant test."],
    "tools": ["agents", "cursor"]
  },
  "plan_id": "the-reviewed-24-character-id",
  "consent": true
}
```
